# @seqno/dom

Logseq 0.10.9's names for seqno's elements, in one table. Logseq themes and plugins select Logseq's class names, ids and attributes (`.ls-block`, `#dot-<uuid>`, `[blockid]`), so every seqno element Logseq also has carries them.

A component names its element once, by its own seqno class, and spreads what `logseq()` returns:

```tsx
<button
  {...logseq("seqno-bullet", { blockId, folded, numbered })}
  data-folded={folded || undefined}
/>
// class="seqno-bullet bullet-container bullet-closed" id="dot-<uuid>" blockid="<uuid>"
```

- The key is the element's seqno class, and `logseq()` puts it first in `className`, so `rg seqno-bullet` finds the CSS, the component and the table entry.
- Each entry links to the Logseq 0.10.9 line that renders it.
- seqno's CSS selects only seqno's names and seqno's `data-*` state, never a Logseq name, so a fix here can't change seqno's own look.
- Code that isn't JSX uses the same output: `element.className = logseq("seqno-plugin-frame").className`.

## What's inside

| Module                                                                  | Exports                                                                                                                                                            |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `index.ts`                                                              | `logseq(part, ...state)`, `names(...tokens)`, `attributesOf` (the same names as plain attributes, for CodeMirror and imperative DOM)                               |
| `block.ts`                                                              | what `block.cljs` renders: rows, bullets, block content, properties, inline refs, embeds, previews, queries                                                        |
| `code.ts`                                                               | code blocks with CodeMirror 5's class names and token classes                                                                                                      |
| `page.ts`                                                               | page, title, page properties, journals, references                                                                                                                 |
| `shell.ts`                                                              | app container, header, both sidebars, menus, tooltips, dialogs, block menu, settings, plugins dialog, the whiteboard welcome and quick tour                        |
| `file.ts`                                                               | Logseq's raw file page: the `.file` wrapper and its title                                                                                                          |
| `editor.ts`                                                             | editor wrapper, CodeMirror editor, autocomplete popup, date picker                                                                                                 |
| `plugins.ts`                                                            | the plugin host: iframes, floating UI, UI slots and injected items                                                                                                 |
| `cmdk.ts`, `content.ts`, `assets.ts`, `pdf.ts`, `slide.ts`, `select.ts` | the command palette, page menu, assets, PDF viewer, slides and graph pickers                                                                                       |
| `document.ts`                                                           | `logseqDocument()`: the `html` and `body` marks (`data-theme`, `data-color`, `is-mac`, `dark-theme`, `data-page`)                                                  |
| `accents.ts`                                                            | `accentStyles`: Logseq's accent colors as `html[data-color]` rules setting the `--ls-*` variables and `--lx-accent-*`/`--lx-gray-*` ramps, from `@radix-ui/colors` |
| `refs.ts`                                                               | `refsSelf`: a block's `data-refs-self` value, as Logseq builds it                                                                                                  |
| `vocabulary.ts`                                                         | generated by `node scripts/logseq-vocabulary.ts [checkout]`: every class and attribute Logseq 0.10.9's stylesheets select and every id its components set          |
| `gaps.ts`                                                               | the names the fixture themes select that seqno doesn't render, each with its reason                                                                                |
| `selectors.ts`                                                          | `selectorNames(css)`: the classes, ids and attributes a stylesheet selects                                                                                         |

Lint `seqno/logseq-names` rejects a name from `vocabulary.ts` written by hand in UI code, and the name check in `tools/e2e/flows/themes.e2e.ts` fails when a name the fixture themes select stops rendering or starts rendering while still listed in `gaps.ts`.

## Cover a new component

1. Find what Logseq 0.10.9 renders for it in `src/main/frontend/components/` at https://github.com/logseq/logseq/tree/0.10.9.
2. Build it from seqno's shared pieces (`Dialog`, `Menu`, `MenuItem`, tooltips, `Popup`), which already carry their Logseq names.
3. Add a row for each of its own Logseq parts to the table file for that Logseq source file, keyed by the element's seqno class, with the 0.10.9 link above it. State that changes Logseq's names is the entry's argument.
4. Spread `logseq("<seqno class>", state)` on the element. seqno's own state goes in `data-*`, and seqno's CSS selects the seqno class, never a Logseq name.
5. Run the themes e2e. If one of the new names was in `gaps.ts`, delete it there.
